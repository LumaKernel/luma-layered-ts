# 付録: Webベストプラクティス

レイヤ仕様と独立したWebフロントエンドの方針。採否は導入時に決める(init.md)。

## 規約の強制方法

見落としが起きたら、修正と同じタスクで同種を検出するテストを置く。

- リポジトリを走査する規約テストを`tools/*.test.ts`に置き、通常のテストと一緒に走らせる。冒頭コメントに元になった失敗を書く
- 走査系テストには、検出器自体の正例・負例のテーブルテストと、走査対象が空でないことの検査を付ける
- 例外は理由付きの許可リスト(`{ "file selector": "理由" }`)に書き、走査結果との完全一致を検査する。新しい該当箇所も、陳腐化した許可も失敗する。許可はファイル単位でなく宣言単位。判断が二択ならリストの値を判断結果にする(`"gutter" | "no-gutter"`)
- CSSは正規表現で読まず、ネストを平坦化して`&`を解決する共有の読取器で読む。TS/TSXはASTで読む
- jsdomで出ない性質(レイアウト、ブラウザだけの警告)は、原因となる構造やパターンをテストで固定し、実測はQAスクリプトで行う
- CLAUDE.mdが参照するパスの実在をテストする
- lint設定をテストする。`lintText(code, { filePath })`で、効くべきパスでerror、除外パスで通ることを確かめる(globの誤りで素通りになる)
- 新ルールの段階導入では、違反ファイルの一覧だけをoffにして一覧をテストで固定する
- 規則を追加したら違反を1つ入れて対応テストが落ちることを、修正を部分ごとに戻すと対応テストが落ちることを確かめる
- 副作用importで埋めるレジストリ(`register*()`, モジュールレベルの可変Map)を作らない。元の定数から型を導いた静的な表にし、追加漏れを型エラーにする

## TypeScript・lint

- typescript-eslintは`strictTypeChecked`をテストにも適用する。autofixのコミットはルールごとに分け、手修正と混ぜない
- `noUncheckedIndexedAccess`を有効にし、`!`を使わない。代わりに名前付きアクセサ(範囲外はnull)、不変条件用の`mustGet`(無ければ名前付きでthrow)、テスト用の`defined()`。無効のままだと`no-unnecessary-condition`が必要なガードを不要と誤報する
- `no-unsafe-*`を有効にする。種別ごとに型が変わるものは、型対応表と存在型をコールバックで渡す形(`withKit(type, v, (kit) => …)`)で`any`を避ける
- `switch-exhaustiveness-check`は`considerDefaultExhaustiveForUnions: false`
- 採用しないlintルールも理由付きで表にする。違反0のルールも有効にする

## CSS

ブラウザサポートは主要ブラウザの直近の安定版。全ブラウザが持つ機能に`@supports`もベンダープレフィックスも書かない。古のハックを使わず最新の機能で書く。

- 色は`oklch()`。`rgb()`/`rgba()`/hexをCSSにもTSXの文字列にも書かない
- テーマで変わる色は`light-dark()`かトークンで書く。`.dark`クラスは`<html>`の`color-scheme`を切り替えるだけにし、コンポーネントのCSSに`.dark`配下のブロックを書かない
- 文字の流れに沿う配置は論理プロパティ。物理方向(画面の隅、図形の幾何、幾何的な中央寄せ)は許可リストに載せる
- `transition: all`を書かない
- `transform: translate*()`でなく`translate`プロパティ(`rotate`/`scale`も同様)
- 円は`border-radius: 50%`でなく`9999px`。Chromeは`50%`を正方形でも楕円として描き、縁のピクセルが変わる
- CSS nesting: 親の直後に続く疑似クラス・属性・複合クラス・子孫だけを入れる。セレクタリストの下に入れない(`&`が`:is()`になり詳細度が変わる)。離れたルールを入れるための並べ替えをしない(カスケード順が変わる)
- CSS Modulesは`@layer components`に入れ、層の中の上書きは詳細度で決める(読み込み順に頼らない)。リセットはvendorした1ファイルに閉じる
- カスタムプロパティの自己参照(`--x: var(--x)`)は黙って無効になる。一部の文脈でしか定義されない変数の`var()`にはフォールバックを書く。両方をテストで禁止する
- 折り返しうる見出しに`text-wrap: balance`、長い本文に`pretty`。CJKの見出し・短いラベルは`word-break: auto-phrase`と`overflow-wrap: anywhere`
- スクロールコンテナごとに`scrollbar-gutter: stable`の要否を決め、全コンテナを判断付きで列挙するテストにする。付けるのは高さに上限があり中身が後から伸びるものだけ
- スクロールする列のflex子要素は`flex-shrink: 0`。`overflow: hidden`の子が縮み、列がスクロールせず内容が到達不能になる
- スマートフォン幅ではドキュメント自体をスクロールさせる(アドレスバーの出し入れはドキュメントのスクロールでのみ起きる)。`body`は`min-block-size: 100lvh`と`overflow-x: clip`。固定高のアプリフレームは広い幅に限る
- CSS Modulesは`view-transition-name`/`view-transition-class`もハッシュ化する。グローバルなキーフレームや`::view-transition-*`から参照するものはグローバルCSSに置き、コンポーネントは属性で指定する

## モーション

- アニメーションには同じセレクタの`prefers-reduced-motion: reduce`ルールを付ける(ネスト由来のアニメーションを別セレクタで止めると詳細度で負ける)。全アニメーションをテストで検査する
- 押下や開閉で要素の大きさ・位置を変えず、状態は色やリングで示す。easingはオーバーシュートさせない
- 並び順や向きの変更はDOM順を変えて行う。transformで回すとキーボード移動とスクリーンリーダーの順序が見た目と逆になる

## テーマ・色

- テーマは`<head>`内の同期スクリプトで初回描画前に確定する。判定関数は1つにし、`toString()`で埋め込んでアプリ側と食い違わせない。`<html>`にだけ`suppressHydrationWarning`を付ける
- WCAGコントラストをソースの色値から計算するテストを置く(ブラウザで測ってはじめて見つかる不合格を防ぐ)
  - CSSの読取器でセレクタの`color`/`background-color`を取り出す。値が無い・`oklch()`として読めないときは、セレクタ名を出して失敗させる(読めない色を黙って飛ばさない)
  - `light-dark(L, D)`はトップレベルのカンマで分け(`color-mix()`の引数の中では分けない)、両テーマの値で測る。ライトだけの検査はダークの不合格を見逃した
  - oklch → OKLab(`a = C·cos h`, `b = C·sin h`) → Björn Ottossonの行列で線形sRGB → [0, 1]にクランプ。相対輝度は線形値に`0.2126 R + 0.7152 G + 0.0722 B`(線形化済みなのでsRGBのガンマ展開は不要)。比は`(明 + 0.05) / (暗 + 0.05)`
  - 計算器自体を、黒/白が21:1になることと、ブラウザで一度実測した組の値を再現することで検査する
  - 前景と、実際にその上に乗る背景の組を列挙する(選択行の背景上のバッジ等)。文字は4.5:1、`aria-hidden`でラベルが状態を伝えている記号は非テキスト指標として3:1
- テーマで変わってはいけない要素(図など)は前景色を継承させず色を明示する

## アクセシビリティ

- マウスとキーボードで完全に等価な操作ができること。複合ウィジェットはWAI-ARIA APGのパターンに従う
- UIプリミティブはヘッドレスライブラリ(React Aria等)を使い、自作しない
- テストは role・アクセシブル名・`aria-*`で状態を確かめる。ARIAで表せない状態だけ`data-*`(値は型のunion)。テストファイルでのclassName参照とクラスセレクタをlintで禁止する
- 可視ラベルのないコントロールは`aria-label`で名前を付ける。視覚的に隠したラベル要素はライブラリによって初回描画で関連付けが欠ける
- 無効表示でも情報を薄くしない

## i18n

- 画面の文言をソースに直書きしない。対象言語の文字種の文字列リテラルをASTで検出するテストで強制し、例外(固有名詞等)は許可リスト
- Storybookのストーリーもアプリと同じ表示関数とメッセージを使う(argsはモジュール読み込み時に固定されロケールを切り替えられない)。同じテストで対象にする
- ロケールをURLに含めるかは意図して決める(含めないならAccept-Languageとcookie)
- E2E・QAスクリプトの期待文言と操作対象の名前はメッセージファイルから読む。長い言語でのはみ出しをE2Eで検査する

## 到達可能性・依存

- `src`の全モジュールとexportがアプリのエントリから到達可能であることを、knipの既定モードと`--production`モード(テストとストーリーからの参照を数えない)をテストから実行して強制する
- UIを追加するタスクは、成果物がアプリから使われていることを確認してから完了にする
- テスト専用のexportはJSDocの`@internal`に理由を書く。「将来使う予定」は理由にしない
- 依存は`--ignore-scripts --save-exact`で入れ、公開から日の浅い版を避ける
- 同じ不変条件を自前テストと外部ツールの2か所で持たない。置き換えるときは同じ違反を検出できることを確かめてから自前を消す

## 実行環境

- polyfillはランタイムが持っていても常に入れ、テストと本番で同じ実行系にする(ローカルのNodeにだけある機能で本番だけ落ちた)。Nodeのメジャー版を`engines`で固定し、`.node-version`等との一致をテストする
- Secure Context限定のAPI(`crypto.randomUUID`等)をlintで禁止するか代替を用意する。LANのHTTPで開くと動かない
- PWAはインストール条件を一次情報で確かめて最小限にし、役目のないService Workerを作らない。manifestとアイコンの寸法・altをテストする

## Next.js

- サーバーで実行されるファイル(`"use client"`のない`app/`配下と、そこから`"use client"`ファイルに至るまでのimport)が`"use client"`モジュールのhookをimportしないことを、importグラフを辿るテストで検査する。jsdomでは発覚せず`next build`のプリレンダーで落ちる
- ビルド成果物を検査するスクリプトを用意する: 動的な`/api`ルートがプリレンダーされていない、CSS Modulesのクラスがモジュールごとのハッシュ接頭辞で出ている(クラス名だけで照合すると別モジュールの同名クラスで合格する)、`:global(`が残っていない、重いpolyfillが意図したチャンクにだけ入っている(barrel exportが全ページに巻き込んだ)
- ビルド検査はpostbuildフックにせず別のnpm scriptにする(デプロイ先のアダプタが出力を移動しデプロイが落ちた)
- `next dev`を別端末から開くには`allowedDevOrigins`に自機のアドレスを入れる。入れないとページは表示されるがHMR等が拒否され動かない

## 時刻・テスト

- 時刻を読むファイルを許可リストで固定する。リクエスト境界で一度だけ読み`now`を引数で渡す。テストは固定の時点から書き、現在時刻からの相対で書かない
- `performance.now()`は端末スリープ中に止まる。経過時間以外に使わない
- シナリオテストは本物のルートハンドラ、in-memory実装、fake clockで通す。`toFake`に`Date`と時刻APIを指定し、タイマーはfakeにしない
- `testTimeout`は停止の検出用に長め(30秒程度)にする。遅さは別に計測する

## ビジュアルQA

`tools/qa/`にスクリプトと手順書を置く。使い捨てのスクリプトもコミットして再利用し、出力のパース部分はstdinフィルタに切り出してテストする。

- 全ストーリー × 両テーマ、全ページ × デスクトップ/モバイル幅を撮影する。各撮影の前に描画できたことを検査する(停止したサーバーのエラーページを撮って「コンソールエラー0件」と報告した)。到達不能なら即座に止める
- 撮影ごとにコンソールエラーを本文・スタック付きで記録し、1件でもあれば失敗させる
- はみ出し検出を撮影に組み込む: 内容が切れている要素、`overflow: visible`の箱から突き出た子、ビューポートにもスクロール可能な祖先の中にもない操作要素。意図した切り詰めは`data-clip-ok`等で除外する
- ダイアログ等は`[role=dialog]`の存在を確かめてから撮る
- ストーリーのdecoratorはアプリでの親要素のレイアウト契約(flexの子であること等)を再現し、対応するCSSと相互にコメントで紐付ける
- 見た目を変えないリファクタは前後のピクセル差分0で合格とし、見た目を変える変更と同じタスクに混ぜない。変更前の撮影は編集前に同じビルド・同じサーバーから取り(再起動するとデータが変わる)、同条件で2回撮って決定性を確かめる
- 差分は外接矩形とピクセル値で特定する。撮影の外れ値は、同じ回の他ページの同領域との比較と撮り直しで見分ける。意図した変更は差分が対象要素の内側に収まることで合格とする。既知のノイズは手順書に列挙する
- hoverは計算済みスタイルを遷移時間待ってから前後で読む
- ヘッドレスChromiumは`--hide-scrollbars`で起動する。クラシックスクロールバーの確認は起動引数から外す
- CSSの書き方だけを変える変更(nesting化等)は、ビルド後のCSSのバイト一致で確かめる。StorybookとアプリでCSSの変換が異なる(片方はネストや`light-dark()`をそのまま出す)ため、計算済みスタイルを両方で確かめる
- 公開物(manifestのスクリーンショット等)は本番ビルドから撮る。本番ビルドでは操作してAPIが追従することを確かめる(ビルド時に固定されたレスポンスはスクリーンショットに現れない)
- ブラウザのロケールを固定する(Playwrightの既定はen-US)
- 実機でしか確かめられないもの(モバイルのアドレスバー等)は利用者の確認が取れるまで合格にしない

## 進め方

- 外部の仕様・規格・ルールを実装するときは、出典(URLと確認日)を設計書と定義箇所のコメントに書く。テストの期待値は出典から書き、実装から写さない(実装の誤りをテストが固定した)
- 設計の最初に、起票時の件数や前提を実測し直す
- 設計書には利用者の原文、比較した選択肢と却下理由、実装とQAで分かったこと、変更時に一緒にすることを書く
- QAで別の不具合を見つけたら新しいタスクにし、完了済みのタスクを戻さない
- タスクは設計→実装→テスト→QA→完了の状態を踏み、QAで不合格なら実装へ戻す。動かせるタスク、完了、外部待ち、人の判断待ちを別ファイルに分け、待ちには解除条件を書く。タスクIDの一意性と、タスクを持たない節が残っていないことをテストする
